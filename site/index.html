● See the loop

How a task moves through VibeCoder

Every task follows the same loop: understand, plan, execute, test, verify, fix, repeat — until the work matches what you actually wanted.

1
Understand Read the request. Detect ambiguity and ask if the goal is unclear.
↓
2
Plan Break the work into steps. Decide which tools and models are needed.
↓
3
Execute Write code, run commands, read files, install packages — one step at a time.
↓
4
Test Run the result. Check it works the way you asked for.
↓
5
Verify Compare the result against your original vision — not just "did it run."
↓
6
Fix If something's off, investigate the failure and try a different approach.
↓
↺
Repeat Loop back until the work is actually right — not just finished.
● Why it exists

Three barriers stood between ideas and built things

VibeCoder started from a real, personal problem. Its creator wanted to build software from an Android phone — without being an experienced programmer and without relying on expensive hardware. Existing coding-agent workflows were built around desktops and capable machines, and that created a gap.

🧠

Knowledge barrier

People have ideas but don't know how to code. They can describe what they want, but the "how" is locked behind a skill they haven't learned yet.

Your idea shouldn't require a CS degree to start.
💻

Hardware barrier

People may know how to build things but can't afford powerful computers. A high-end laptop or workstation shouldn't be a prerequisite for building software.

A low-end phone should still be a valid way to build.
📱

Accessibility barrier

AI coding workflows are often designed around desktop environments and high-resource setups. Mobile and low-resource environments get left out of the conversation entirely.

The work should follow the user, not the hardware.

The original motivation was simple: "I want to be able to build things from my Android phone, even without high-end hardware or traditional coding skills." That grew into a broader philosophy:

"Build the tool you wish existed. Then open the door for others."

● Available now · V1.0.0

What VibeCoder does today

Today, VibeCoder is a single-agent terminal-based AI coding assistant. It receives a natural-language task, uses AI models and tools to do the work, and iterates until the job is done. This is real, usable software — not a roadmap masquerading as a product.

Natural-language tasks

Describe what you want in plain language. The agent reads the request, understands the goal, and starts working.

Available now

CLI, REPL, Unix TUI

Three ways to talk to the agent: a one-shot CLI for task prompts, an interactive REPL for back-and-forth, and a full-screen terminal UI.

Available now

Code generation & editing

Create files, write code, and make surgical edits without clobbering what's already there. The agent reads before it writes.

Available now

File read, search, grep, glob

Explore any codebase. Find the right file and the right line before touching anything — read-only investigation first.

Available now

Terminal command execution

Run shell commands — git, builds, installs, scripts, tests. The agent batches work where it can and never runs destructive commands silently.

Available now

Package installation via shell

Install tools and dependencies through the shell as part of the work, not as a separate setup step you have to manage.

Available now

Model routing

A fast model handles chat and simple queries; a heavy reasoning model takes coding and complex tasks. Use the cheap model all day, the big model when it matters.

Available now

Local Ollama + remote providers

Works with Ollama for local models, plus GROQ, NVIDIA NIM, OpenAI, Anthropic, and any custom OpenAI-compatible endpoint. You choose where the intelligence comes from.

Available now

Queue system + background daemon

Heavy tasks get queued automatically when connectivity drops and run the moment it returns. Work keeps moving on spotty mobile data.

Available now

Tailscale & network diagnostics

Before reaching a server on another device, the agent checks the tailnet tunnel and runs local network checks — ping, DNS, HTTP probe, gateway. If it's down, it tells you rather than guessing at an unreachable IP.

Available now

HTTP URL fetching

Read documentation, API responses, and web pages as part of the agent's reasoning. Capped output so big pages never blow context.

Available now

Step-level error retries

If a tool call fails, the agent retries at the step level before giving up — not every failure becomes an immediate "what should I do?" to you.

Available now

Tool approval & live status

Sensitive actions can require your approval. Streaming shows what the agent is doing as it happens. Tool calls are visible inline.

Available now

Plan mode, config, self-reporting

Plan mode lets the agent think before it acts. A configuration system controls providers, models, and behavior. Self-reporting and self-edit auditing keep a record of what the agent changed and why.

Available now

Timeouts & token budgeting

Each interaction has a timeout and a token budget, so the agent doesn't burn through your context or your patience on a stuck loop.

Available now

Connectivity awareness

The agent knows whether it's online. Offline, it can fall back to a local model (if you have one) or queue work for when connectivity returns.

Available now

Session persistence

Work persists across sessions. The agent can pick up where it left off instead of starting from zero every time.

Available now

Linux, macOS, partial Windows

Runs on Linux and macOS. Windows support is partial but usable — the core agent loop works; some platform-specific tools vary.

Available now

What it does not do yet: VibeCoder v1.0.0 is a single agent, not an orchestrated multi-agent system. It doesn't run parallel agents, create tools at runtime, take mid-task pause/resume, let you modify the goal live, or take over manually during execution. It doesn't have full GitHub integration, browser-based web browsing, a dedicated debugger, wall-clock task deadlines, or cross-session semantic memory. These are the next things — see the roadmap.

● How it works

From your words to working software

The current architecture is straightforward: your request goes through a model router, into an agent loop, out to tools, and back with results. You own every part of that chain — the prompt, the tools, the providers. Nothing is opaque or locked behind a framework.

The agent loop runs up to 40 steps per task — each step is a tool call, an observation, and a decision. If a step fails, the agent retries. If context gets tight, it trims. If the task is still going after 40 steps, it reports what it accomplished and what's left. You're never left guessing what happened.
● Local + remote AI

Provider-agnostic — you choose where the intelligence comes from

VibeCoder is designed to work with local models and remote providers alike. The long-term system stays model-agnostic: you select models manually, and eventually the agent picks the right one for the task automatically.

● The long-term vision

Where VibeCoder is going

Today's VibeCoder is a real, usable single-agent assistant. The larger vision is an autonomous AI software specialist — something closer to a software-focused JARVIS/FRIDAY than a chatbot or code generator. This is the direction the project is being built toward, not what exists today.

Vision — not yet implemented

An autonomous software specialist

The goal is to let a person describe what they want to build and have VibeCoder understand the goal, plan the work, execute it, test it, verify it, fix problems, and continue working toward the user's actual vision — without the user having to manually control every tiny step.

🎯

Dynamic agents

For complex tasks, create and assign specialized agents — research, frontend, backend — based on what the work actually needs.

↔️

Parallel work

Independent components of a task worked on in parallel where it makes sense — not "more agents," but the right agents for the right task.

🔁

Continuous verification

The agent compares results against your original vision and repeats the understand-plan-execute-test-verify-fix loop until the work is actually right.

🛡️

Self-recovery

Failure triggers investigation, not immediate surrender. Inspect errors, read docs, try another approach or model, test again.

⏱️

Long-running tasks

"You have 6 hours. Work on this until it's finished." The agent plans around the time available, prioritizes, leaves room for testing and fixes, and stops when the work is done.

📱→💻→☁️

Multi-device execution

The same work moving across phone, PC, server, cloud, and other connected devices — your hardware shouldn't be the reason the work stops.

● Open source

Built public because building shouldn't have another paywall

VibeCoder is open source because its creator doesn't want someone who loves building things to hit another mandatory paywall at every stage. Building software already has possible costs — hardware, infrastructure, APIs, hosting, deployment, services. VibeCoder itself should not become one more barrier that makes someone abandon an idea because they can't afford the tool.

The philosophy

"If someone has an idea and wants to build it, their lack of coding knowledge or expensive hardware should not automatically stop them."

No business model (yet)

There is no decided monetization strategy. No subscriptions, no enterprise pricing, no premium tiers, no ads. The long-term personal vision is for the complete VibeCoder experience to eventually be free, including the infrastructure.

● Roadmap

● Install

Get running in a few minutes

Clone the repo, install dependencies, set a free API key, and you're talking to your agent. No PC required if you're on Android Termux. No opaque setup dance.

1

Clone the repository

git clone https://github.com/akashjoshi1209/vibecoder.git && cd vibecoder
2

Install dependencies (Bun + npm)

npm install && bun run build
3

Set a free API key in a gitignored .env

echo "GROQ_API_KEY=your_key_here" > .env

GROQ (qwen3.8-27b, gpt-oss-120b) and NVIDIA NIM (Nemotron 3 Ultra 550B) both have free tiers. Or point it at any OpenAI-compatible endpoint.

4

Start the agent

./vibecoder

Describe what you want to build. The agent understands, plans, executes, tests, verifies, and iterates until it's done.

● Who it's for

Anyone with an idea they want to turn into software

VibeCoder is not only for professional developers. It's for complete beginners, students, makers, indie hackers, people with only an Android phone, people on low-end computers, people with powerful workstations, and anyone already using AI coding agents. A beginner should understand the website. A developer should still find enough technical depth to take the project seriously.

On the go

Quick coding sessions

Write a script, fix a bug, build a small tool — between things, on the train, on the couch. No laptop required. You describe the outcome; the agent does the work.

Building

Build real things

The heavy model takes on real coding tasks — multi-file work, debugging, refactoring. The agent keeps context across steps and tool calls until the job is done.

Exploration

Understand any codebase

Drop into a project, ask the agent to explain it, trace how pieces fit together, and grep for the thing you actually care about. Read-only investigation before you touch anything.

Offline-resilient

Spotty data? No problem

Heavy tasks queue automatically when connectivity drops and run when it returns. You can keep talking to the agent on a local model (if you have one) or queue work for later.

Multi-device

Reach your other machines

With Tailscale up, the agent checks the tunnel and reaches a server on another device — your home server, a VPS, a NAS. One agent, several machines, from wherever you are.

Low-spec

Build on modest hardware

A low-end phone or a modest laptop is still a valid way to access the system. The agent uses whatever hardware is available and, eventually, reaches for more when the task needs it.
